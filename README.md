# VALORANT 核心模块测试与自动化分析

这是一个面向游戏测试/测试开发岗位的作品集项目：以《无畏契约》可公开观察的竞技对局为业务背景，用 Python + pytest 验证对局状态机、局内经济、技能与伤害、接口契约、弱网故障、断线重连和日志可观测性。

> 边界声明：本项目不是拳头游戏或腾讯官方项目，不连接非公开服务，也不声称复刻真实服务端。规则参数可配置，测试重点是多人在线游戏中通用的质量风险。

## 项目亮点

- 将“排队→选人→加载→对局→结算”抽象为有限状态机，覆盖合法路径与非法跳转。
- 对购买、退款、回合结算建立幂等约束，防止网络重试导致重复扣款或重复加分。
- 模拟断线重连，以服务端权威快照恢复阶段、回合与比分，拒绝客户端旧状态覆盖。
- 建立可重复的网络故障通道，参数化覆盖 0/50/200/500ms 延迟及丢包、重复包、乱序组合。
- 对购买、回合结算和重连事件执行字段类型、必填项、版本及时间戳契约校验。
- 使用等价类、边界值、状态迁移、场景法和错误推测设计自动化用例。
- 流式处理 JSONL 日志，筛选 ERROR 前后文、按时间排序并导出 CSV；使用10万条模拟事件验证规模处理。
- 当前自动化回归共收集122个pytest场景，全部通过；数量以实际测试收集结果为准。

## 运行

```powershell
python -m pip install -e ".[dev]"
python -m pytest -v
python -m valorant_qa.log_analyzer test_data/sample_match.jsonl reports/errors.csv --radius 2
python -m valorant_qa.scale_analysis --records 100000 --output reports/scale_report.json
```

## 关键质量不变量

1. 余额始终在 `[0, max_credits]` 范围内。
2. 失败购买不能改变余额、库存或交易记录。
3. 相同 request_id 不能造成二次扣款/奖励。
4. 相同 round_event_id 不能重复改变比分。
5. 非法状态跳转必须被拒绝。
6. 重连后采用服务端权威状态，而不是客户端旧快照。
